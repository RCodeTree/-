`set` 是 Linux Shell（如 Bash）中一个功能强大且复杂的内置命令，它主要用于**显示或设置 Shell 变量和 Shell 选项**，从而定制 Shell 脚本的运行环境。由于其功能众多，在 GNU Bash 手册中，它甚至被单独列为一个小节进行说明。

### 📜 基本语法与核心机制

`set` 命令的通用语法如下：

```bash
set [选项] [参数...]
```

它的核心工作机制围绕两个符号展开：
*   **`-` (减号)**：**开启**（设置）指定的 Shell 选项。
*   **`+` (加号)**：**关闭**（取消）指定的 Shell 选项。

当**不带任何选项和参数**执行 `set` 命令时，它会显示当前 Shell 中所有已定义的变量和函数，格式为 `name=value`，并且输出可以重新作为输入来恢复当前设置。

### ⚙️ 常用选项详解

`set` 的选项非常多，下表汇总了最常用和最重要的选项。大多数单字符选项都有一个对应的长选项名，可以通过 `-o` 来设置。

| 短选项 | 长选项 (`-o`) | 功能说明 |
| :--- | :--- | :--- |
| **`-e`** | `errexit` | **遇错即停**：如果任何命令返回非零状态码（即执行失败），立即退出 Shell。这在脚本中用于快速失败。 |
| **`-u`** | `nounset` | **禁用未定义变量**：当尝试使用一个未定义的变量时，将其视为错误并退出。这有助于捕捉拼写错误。 |
| **`-x`** | `xtrace` | **调试模式**：在执行每条命令前，先将其打印出来。这是排查脚本逻辑错误最常用的工具。 |
| **`-f`** | `noglob` | **禁用通配符**：关闭文件名扩展（globbing），即禁止使用 `*`、`?` 等通配符来匹配文件名。 |
| **`-C`** | `noclobber` | **禁止覆盖**：在使用重定向 `>` 时，禁止覆盖已存在的文件，可以防止意外数据丢失。 |
| **`-a`** | `allexport` | **自动导出**：所有创建或修改的变量自动标记为导出，对后续命令可见。 |
| **`-n`** | `noexec` | **只读不执行**：读取命令但不实际执行，用于语法检查。 |
| **`-v`** | `verbose` | **显示输入**：在读取 Shell 输入行时将其打印出来。 |
| **`-m`** | `monitor` | **启用监控模式**：开启作业控制功能。 |
| **`-b`** | `notify` | **后台任务通知**：当后台任务终止时立即报告，而不是等到下一个提示符出现。 |

### 💡 核心应用场景

#### 1. 脚本调试与错误处理（最常用）

在实际的 Shell 脚本编写中，`set` 命令是保证脚本健壮性的利器。一个非常经典的实践是在脚本开头加上 **`set -euxo pipefail`**，这组选项的组合能极大提升脚本的可靠性。

*   **`set -e`**：确保脚本在任何一个命令失败时立即停止，避免错误累积和后续的误操作。
*   **`set -u`**：强制要求所有变量都必须先定义后使用，防止因变量名为空而导致的意外行为。
*   **`set -x`**：提供详细的执行跟踪，方便调试。在生产环境中，也可以利用 `set +x` 在特定段落临时关闭调试输出。
*   **`set -o pipefail`**：**专门针对管道**。默认情况下，管道命令的退出状态是最后一个命令的退出状态。开启 `pipefail` 后，只要管道中任何一个命令失败，整个管道的退出状态就是非零（失败），从而使 `set -e` 能正确捕获管道中的错误。

你可以根据需要，在脚本中分段开启或关闭这些选项：

```bash
#!/bin/bash
# 调试某段代码时开启
set -x
echo "这段代码会被详细跟踪"
set +x # 关闭调试

# 在关键操作前开启错误退出
set -e
rm important_file.txt
echo "如果上面的 rm 失败，这行不会执行"
```

#### 2. 操作位置参数

`set` 命令可以用来**设置或重置脚本的位置参数**（`$1`, `$2`, ...）。这在需要重新组织或解析参数时非常有用。

```bash
#!/bin/bash
echo "原始参数: $@"
# 使用 -- 来设置新的位置参数
set -- "new_arg1" "new_arg2" "new_arg3"
echo "新参数1: $1"
echo "新参数2: $2"
echo "所有新参数: $@"
```
执行 `./script.sh old1 old2`，输出将是 `new_arg1` 和 `new_arg2`。

#### 3. 导出变量到环境

使用 `-a` 选项，可以让 Shell 中定义的变量自动成为环境变量，对后续执行的子进程可见。

```bash
set -a
MY_VAR="hello"
# 此时 MY_VAR 已经被导出
bash -c 'echo $MY_VAR' # 输出 hello
```
需要注意的是，在较新的 Bash 版本中，通常更推荐使用 `export` 命令来显式地导出变量。

### ⚠️ 注意事项

*   **作用范围**：`set` 设置的选项仅对**当前 Shell 环境**有效，不会被继承到子 Shell 中。如果希望子 Shell 也使用相同的选项，需要在子 Shell 中重新设置，或者通过环境变量传递。
*   **`-e` 的例外情况**：`set -e` 并非在所有失败场景下都会退出。例如，在 `if` 语句的条件、`while`/`until` 循环的条件、`&&` 或 `||` 列表中的非最终命令，以及被 `!` 取反的命令中，失败不会触发 `-e` 退出。需要理解这些例外，才能正确使用它。
*   **与 `shopt` 命令的区别**：`set` 控制的是 POSIX 标准的 Shell 选项，而 `shopt` 用于控制 Bash 特有的、非 POSIX 的选项，两者功能互补。

`set` 命令是每个 Shell 脚本开发者都应该熟练掌握的工具。它在调试、错误处理和脚本环境控制方面提供的灵活性，是编写健壮、可维护脚本的基础。


*** 


`trap` 是 Shell（Bash、sh 等）的内置命令，用于**捕获信号**或**Shell 特殊事件**，并指定要执行的动作。它是编写健壮脚本、实现优雅退出、资源清理和错误处理的核心工具。与 `set` 命令类似，`trap` 的设置仅作用于当前 Shell 进程，但信号处理是异步的，理解其触发时机和继承规则非常重要。

---

## 📜 基本语法

```bash
trap [-lp] [[动作] 信号...]
```

- **动作**：收到指定信号或事件时执行的命令，通常用单引号包裹。
- **信号**：信号名称（如 `INT`、`TERM`）或编号（如 `2`、`15`），可带 `SIG` 前缀。也可使用特殊伪信号 `EXIT`、`ERR`、`DEBUG`、`RETURN`。
- **常用形式**：
  - `trap '命令' 信号...`：捕获信号，执行命令。
  - `trap '' 信号...`：忽略信号（空动作）。
  - `trap - 信号...`：重置为默认动作。
  - `trap` 或 `trap -p`：列出当前所有陷阱。
  - `trap -l`：列出系统支持的所有信号名称和编号。

## 📡 信号与特殊伪信号

### 常见信号

| 信号 | 编号 | 默认行为 | 说明 |
| :--- | :--- | :--- | :--- |
| `SIGHUP` | 1 | 终止 | 终端挂断，常用于让守护进程重载配置 |
| `SIGINT` | 2 | 终止 | 键盘 `Ctrl+C` |
| `SIGQUIT` | 3 | 终止+核心 | 键盘 `Ctrl+\` |
| `SIGKILL` | 9 | 终止 | **不可捕获、不可忽略** |
| `SIGTERM` | 15 | 终止 | `kill` 默认信号，优雅终止 |
| `SIGSTOP` | 19 | 暂停 | **不可捕获、不可忽略** |
| `SIGTSTP` | 20 | 暂停 | 键盘 `Ctrl+Z` |
| `SIGUSR1` | 10 | 终止 | 用户自定义 |
| `SIGUSR2` | 12 | 终止 | 用户自定义 |
| `SIGCHLD` | 17 | 忽略 | 子进程状态改变 |
| `SIGPIPE` | 13 | 终止 | 向无读端的管道写入 |

> 信号编号因架构可能不同，脚本中建议使用名称。用 `trap -l` 或 `kill -l` 查看完整列表。

### 特殊伪信号（Bash 特有）

| 伪信号 | 触发时机 | 说明 |
| :--- | :--- | :--- |
| `EXIT` | Shell 退出时 | 无论正常 `exit` 还是收到未捕获信号导致退出，都会执行。常用于清理。 |
| `ERR` | 命令返回非零状态时 | 类似 `set -e` 的钩子，但可自定义动作。受条件上下文影响。 |
| `DEBUG` | 每个简单命令、`for`/`case` 等执行前 | 可用于调试，`$BASH_COMMAND` 保存即将执行的命令。 |
| `RETURN` | 函数返回或 `source` 执行完毕时 | 需要 `set -T` 才能被函数继承。 |

## ⚙️ 常用操作

### 1. 设置陷阱

```bash
# 捕获 SIGINT，执行自定义动作
trap 'echo "捕获到 Ctrl+C"; exit 130' INT

# 捕获多个信号，执行同一动作
trap 'cleanup' INT TERM EXIT
```

### 2. 忽略信号

```bash
trap '' INT    # 之后 Ctrl+C 对本 Shell 无效
```

### 3. 重置为默认动作

```bash
trap - INT     # 恢复 SIGINT 的默认行为
```

### 4. 查看当前陷阱

```bash
trap -p        # 列出所有陷阱，输出可重新执行以恢复
trap -p INT    # 仅查看 INT 的陷阱
```

### 5. 列出所有信号

```bash
trap -l
```

## 💡 典型应用场景与示例

### 1. 资源清理（最常用）

利用 `EXIT` 伪信号，确保脚本无论因何退出都能清理临时文件。

```bash
#!/bin/bash
tmpfile=$(mktemp)
cleanup() {
    echo "正在清理临时文件: $tmpfile"
    rm -f "$tmpfile"
}
trap cleanup EXIT

echo "一些数据" > "$tmpfile"
# 脚本结束或中途出错，都会自动执行 cleanup
```

### 2. 优雅处理中断信号

```bash
#!/bin/bash
tmpfile=$(mktemp)

cleanup() {
    echo "收到终止信号，正在清理..."
    rm -f "$tmpfile"
}
trap cleanup EXIT
trap 'echo "捕获到 SIGINT"; exit 130' INT
trap 'echo "捕获到 SIGTERM"; exit 143' TERM

echo "运行中，按 Ctrl+C 测试..."
sleep 100
```

> 注意：信号处理中调用 `exit` 会触发 `EXIT` 陷阱，因此清理逻辑放在 `EXIT` 中可避免重复。

### 3. 忽略 Ctrl+C

```bash
trap '' INT
echo "现在按 Ctrl+C 不会中断本脚本"
sleep 10
```

### 4. 错误处理（ERR 陷阱）

```bash
#!/bin/bash
set -e
trap 'status=$?; echo "错误: 命令 \"$BASH_COMMAND\" 失败，行号 $LINENO，状态 $status"' ERR

false
echo "这行不会执行"
```

> `ERR` 陷阱在命令返回非零时触发，但以下情况不触发：`if` 条件、`while`/`until` 条件、`&&`/`||` 的非最后命令、`!` 取反命令等。

### 5. 调试（DEBUG 陷阱）

```bash
trap 'echo "即将执行: $BASH_COMMAND"' DEBUG
echo hello
ls /tmp
```

### 6. 信号转发

在包装脚本中捕获 `TERM` 并转发给子进程：

```bash
#!/bin/bash
child_pid=
trap 'kill -TERM $child_pid 2>/dev/null' TERM

sleep 100 &
child_pid=$!
wait $child_pid
```

### 7. 保存与恢复陷阱

```bash
old_trap=$(trap -p INT)
trap 'echo "新的 INT 处理"' INT
# ... 某些操作 ...
eval "$old_trap"   # 恢复原来的陷阱
```

## 🔍 高级细节与注意事项

### 1. 引号的使用

- **单引号**：延迟展开，信号发生时才展开变量。  
  `trap 'echo $foo' EXIT` —— 退出时读取 `$foo` 的当前值。
- **双引号**：立即展开，设置陷阱时就确定内容。  
  `trap "echo $foo" EXIT` —— 设置时 `$foo` 的值被固定。

通常推荐单引号。

### 2. 保存退出状态

在 `EXIT` 陷阱中，`$?` 保存的是脚本退出状态，但执行其他命令会覆盖它。应先保存：

```bash
trap 'status=$?; cleanup; exit $status' EXIT
```

### 3. 不可捕获的信号

`SIGKILL` (9) 和 `SIGSTOP` (19) 无法被捕获或忽略。`kill -9` 会直接杀死进程，不执行任何陷阱。

### 4. 子 Shell 与继承

- `trap` 设置**不会**通过 `exec` 传递给新程序；新程序会重置信号处理。
- 对于 `fork` 出的子 Shell（如 `( ... )`、命令替换），Bash 通常会将陷阱重置为默认，但**被忽略的信号**（`trap ''`）会保留。
- 若希望 `ERR` 陷阱在函数或子 Shell 中生效，需 `set -E`（`errtrace`）。
- 若希望 `RETURN` 陷阱被函数继承，需 `set -T`（`functrace`）。

### 5. 信号处理时机

Bash 会等待当前前台命令执行完毕，再处理信号并执行陷阱。如果信号到达时正在执行外部命令，该命令可能也会收到信号（取决于进程组）。因此，长时间运行的外部命令需要自行处理信号或通过 `wait` 配合。

### 6. 函数中的 trap 作用域

`trap` 没有局部作用域，在函数中设置会影响整个 Shell。若需临时修改，应保存原陷阱并在函数结束时恢复。

### 7. 与 `set -e` 的关系

`set -e` 让 Shell 在命令失败时立即退出；`trap ERR` 则提供自定义错误处理。两者可共存：`ERR` 陷阱先执行，然后 `set -e` 触发退出。但要注意 `set -e` 的例外情况，`ERR` 陷阱同样受这些条件影响。

### 8. 列出陷阱的可恢复性

`trap -p` 的输出格式为 `trap -- '动作' 信号`，可以直接用 `eval` 重新执行以恢复。

---

## 📝 总结

`trap` 是 Shell 脚本中处理信号和特殊事件的核心命令。掌握它可以实现：

- **资源清理**：`EXIT` 陷阱确保临时文件、锁、网络连接等被释放。
- **优雅退出**：捕获 `INT`、`TERM`，执行清理后以正确状态码退出。
- **错误处理**：`ERR` 陷阱记录错误上下文，辅助调试。
- **调试跟踪**：`DEBUG` 陷阱打印执行命令。
- **信号转发**：包装脚本将信号传递给子进程。

关键要点：使用单引号延迟展开；保存 `$?`；记住 `SIGKILL`/`SIGSTOP` 不可捕获；子 Shell 中陷阱可能重置；`set -E`/`set -T` 控制继承。熟练运用 `trap`，能显著提升脚本的健壮性和可维护性。
