# Shell

``` bash
if [ 条件 ]; then
    条件成立时执行
else
    条件不成立时执行
fi
```

``` bash
for [条件]; do
    循环体
done
```

``` bash
while [条件]; do
    循环体
done
```

---

## 条件判断写法

| 写法 | 含义 |
|------|------|
| `[ -f file ]` | 文件是否存在 |
| `[ -d dir ]` | 目录是否存在 |
| `[ -z "$var" ]` | 变量是否为空 |
| `[ "$a" = "$b" ]` | 字符串相等 |
| `[ $n -gt 100 ]` | 数字大于 100（`-gt` 大于，`-lt` 小于，`-eq` 等于） |

## 三种执行方式的本质区别（⚠️ 重点，面试常考）

同一个脚本，三种跑法结果看着一样，但**底层完全不同**：

| 方式 | 是否子进程 | 是否需要执行权限 | 变量是否影响当前终端 |
|------|-----------|----------------|---------------------|
| `./hello.sh` | ✅ 新开子进程 | ✅ 需要 | ❌ 不影响 |
| `bash hello.sh` | ✅ 新开子进程 | ❌ 不需要 | ❌ 不影响 |
| `source hello.sh` / `. hello.sh` | ❌ 当前 shell | ❌ 不需要 | ✅ **会污染当前终端** |

**用实验验证 `source` 的"污染"问题，这是理解关键：**

`先给脚本里加一个变量，改成这样：`

```bash
#!/bin/bash
NAME="trae"
echo "脚本内部 NAME = $NAME"
```

然后依次执行（注意 `./` 和 `source` 的区别）：

```bash
./hello.sh          # 脚本打印 NAME = trae
echo "脚本外 NAME = $NAME"   # 结果为空 → 子进程里变量消失了

source hello.sh     # 脚本打印 NAME = trae
echo "脚本外 NAME = $NAME"   # 结果 = trae → 变量泄漏到当前终端！
```

**结论（SRE 视角）：**
- 平时跑脚本，统一用 `./脚本名` 或 `bash 脚本名`，**不要让变量泄漏**。
- `source` 专门用于"加载配置/环境变量"的场景，比如 `source /etc/profile`、`source venv/bin/activate`，这是它的正确用法。
