# 每日 Shell 运维实战练习 · 2026-09-18

## 题目：目录全量备份脚本（backup.sh）

### 题目背景

作为运维，你经常需要把某个业务目录（例如 `/var/www/html`、`/etc/nginx`）定时备份到备份盘，防止误删或磁盘故障导致数据丢失。一个合格的备份脚本必须满足：**失败时不留下损坏的半成品备份**、**全程有可读日志**、**中断时能自动清理**。

今天这道题用于**巩固基础**，把前面学过的知识串成一件可复用的运维工具：函数、退出码、参数校验、`set -euo pipefail`、`trap` 清理、日志函数、`tar`、`date`、`mktemp`、`basename`、`du`。

> 注意：本脚本只“读”源目录、“写”备份目录，属于安全的练习。建议先用一个小的测试目录（如 `mkdir -p /tmp/demo/www` 里放几个文件）验证。

## 脚本编写要求

编写 `backup.sh`，实现以下功能：

1. Shebang 使用 `#!/bin/bash`，开头开启 `set -euo pipefail`。
2. 定义三个日志函数（带颜色 + 时间戳）：
   - `log_info`（绿色）
   - `log_warn`（黄色）
   - `log_error`（红色，输出到 stderr）
3. **参数校验**：接收两个参数 `<源目录>` 和 `<备份目录>`：
   - 参数个数不为 2：用 `log_error` 打印用法和示例，退出码 `2`。
   - 源目录不存在或不是目录：打印错误，退出码 `1`。
   - 源目录不可读：打印错误，退出码 `1`。
   - 备份目录不存在时用 `mkdir -p` 自动创建；创建失败则报错退出。
4. **备份文件名**：`源目录名_YYYYMMDD_HHMMSS.tar.gz`（时间戳用 `date` 生成），放在备份目录下。
5. **打包**：使用 `tar -czf` 将源目录打包成 `.tar.gz`。打包时进入源目录的父目录再打包 `basename`，避免压缩包内出现绝对路径。
6. **防半成品（核心）**：先打包到一个**临时文件**，全部校验通过后再用 `mv` 原子改名为最终文件名。这样只要最终 `.tar.gz` 存在，就一定是完整备份。
7. **trap 清理**：用 `trap` 捕获 `EXIT`/`INT`/`TERM`，保证脚本被 `Ctrl+C` 或 `kill` 中断时，自动删除未完成的临时文件。
8. **打包后校验**：
   - 临时文件非空（`-s` 判断）；
   - `tar -tzf` 能正常列出内容（压缩包未损坏）；
   - 打印备份文件大小（`du -h`）。
9. **日志完整**：开始备份、备份完成时都要打日志，完成时打印备份文件的**完整绝对路径**和大小。

## 验收标准

1. 传错参数时能友好报错，且退出码正确（`2`）。
2. 源目录不存在时退出码为 `1` 并打印错误。
3. 正常备份后，用 `tar -tzf <备份文件> | head` 能正确列出源目录里的文件。
4. 备份过程中按 `Ctrl+C`，备份目录里**不会**留下 `.tar.gz` 半成品文件（临时文件会被清理）。
5. 重复运行两次，能生成两个不同时间戳的备份文件，互不覆盖。

## 参考答案（写完后对照）

```bash
#!/bin/bash
set -euo pipefail

# ==================== 日志函数 ====================
log_info()  { echo -e "\033[32m[INFO]  $(date '+%F %T') $*\033[0m"; }
log_warn()  { echo -e "\033[33m[WARN]  $(date '+%F %T') $*\033[0m"; }
log_error() { echo -e "\033[31m[ERROR] $(date '+%F %T') $*\033[0m" >&2; }

# ==================== 全局变量 ====================
SRC_DIR=""
BACKUP_DIR=""
TMPFILE=""          # 临时打包文件，供 trap 清理

# ==================== 清理函数 ====================
# 只清理"未完成"的临时文件；完成后会清空 TMPFILE，避免误删最终文件
cleanup() {
    if [ -n "$TMPFILE" ] && [ -f "$TMPFILE" ]; then
        rm -f "$TMPFILE"
        log_warn "已清理未完成的临时文件: $TMPFILE"
    fi
}
trap cleanup EXIT
trap 'exit 130' INT    # Ctrl+C
trap 'exit 143' TERM   # kill

# ==================== 参数校验 ====================
if [ $# -ne 2 ]; then
    log_error "用法: $0 <源目录> <备份目录>"
    log_error "示例: $0 /var/www/html /backup"
    exit 2
fi

SRC_DIR="$1"
BACKUP_DIR="$2"

if [ ! -d "$SRC_DIR" ]; then
    log_error "源目录不存在或不是目录: $SRC_DIR"
    exit 1
fi

if [ ! -r "$SRC_DIR" ]; then
    log_error "源目录不可读: $SRC_DIR"
    exit 1
fi

if ! mkdir -p "$BACKUP_DIR"; then
    log_error "无法创建备份目录: $BACKUP_DIR"
    exit 1
fi

# ==================== 生成文件名 ====================
STAMP="$(date '+%Y%m%d_%H%M%S')"
BASE_NAME="$(basename "$SRC_DIR")"
FINAL_FILE="${BACKUP_DIR}/${BASE_NAME}_${STAMP}.tar.gz"

log_info "开始备份: $SRC_DIR -> $FINAL_FILE"

# ==================== 打包到临时文件 ====================
# 临时文件放在备份目录下，确保与最终文件同一文件系统，mv 才是原子操作
TMPFILE="$(mktemp "${BACKUP_DIR}/.backup_${BASE_NAME}.XXXXXX")"

# -C 进入源目录父目录，再打包 basename，避免压缩包内出现绝对路径
if ! tar -czf "$TMPFILE" -C "$(dirname "$SRC_DIR")" "$BASE_NAME"; then
    log_error "打包失败: $SRC_DIR"
    exit 1
fi

# ==================== 校验 ====================
if [ ! -s "$TMPFILE" ]; then
    log_error "备份失败：生成的压缩包为空"
    exit 1
fi

if ! tar -tzf "$TMPFILE" >/dev/null 2>&1; then
    log_error "备份失败：压缩包校验未通过"
    exit 1
fi

# ==================== 原子改名 ====================
mv "$TMPFILE" "$FINAL_FILE"
TMPFILE=""   # 清空，EXIT 陷阱不再清理（此时文件已完整）

SIZE="$(du -h "$FINAL_FILE" | cut -f1)"
log_info "备份完成: $FINAL_FILE (大小: $SIZE)"
```

## 关键点讲解与运维最佳实践

1. **为什么要“临时文件 + 原子改名”？**
   如果直接 `tar -czf 最终文件`，一旦打包中途断电/中断，磁盘上会留下一个**看起来存在、实则损坏**的 `.tar.gz`。先写临时文件、校验通过后再 `mv`，能保证“最终文件出现 = 一定完整”。临时文件放在备份目录内（同一文件系统），`mv` 才是原子操作，不会跨盘复制。

2. **trap 的写法为什么分三条？**
   `trap cleanup EXIT` + `trap 'exit 130' INT` + `trap 'exit 143' TERM`：收到 `INT`/`TERM` 时先执行 `exit`，`exit` 又会触发 `EXIT` 陷阱去跑 `cleanup`，清理逻辑只写一份、不会重复执行。`130 = 128 + 2(SIGINT)`，`143 = 128 + 15(SIGTERM)`，这是信号退出码的约定。

3. **`set -euo pipefail` 与 `if ! tar ...` 的配合。**
   `set -e` 会在命令失败时退出；但 `if ! tar ...` 中 `tar` 处于 `if` 条件里，失败**不会**触发 `set -e`，由我们显式 `log_error` + `exit 1` 处理，错误提示更清晰。这是“快速失败”和“友好报错”兼得的常见写法。

4. **`-C "$(dirname "$SRC_DIR")" "$BASE_NAME"` 的作用。**
   直接用 `tar -czf x.tar.gz /var/www/html` 会把 `/var/www/html` 这样的绝对路径存进压缩包，解压时会还原到原路径，既不安全也不方便。用 `-C` 切换到父目录再打包目录名，解压出来就是干净的 `html/`。

5. **备份目录内用 `mktemp` 的好处。**
   `mktemp` 原子地生成一个唯一临时文件名，避免并发运行两个备份脚本时文件名冲突。放在备份目录内（而非 `/tmp`）还能保证同一文件系统，让 `mv` 保持原子。

6. **退出码语义约定。**
   `0` 成功；`1` 一般运行错误；`2` 用法错误（这是 `grep` 等命令沿用的惯例）。区分退出码便于上层调度脚本或 cron 判断失败原因。

### 进阶提示（下一阶段再扩展）

- 备份前用 `df` 检查备份盘剩余空间是否足够（防止备份到一半磁盘写满）。
- 增加 `--keep N` 参数，备份完成后自动删除超过 N 天的旧备份。
- 记录备份日志到文件（`log_info` 同时 `tee -a` 到日志文件），方便事后审计。
