# 每日 Shell 运维实战练习 · 2026-09-20

## 题目：Nginx 访问日志分析脚本（log_analyzer.sh）

### 题目背景

前两题你练的是"备份"（文件操作 + 参数解析 + 安全）。今天换个战场——**日志分析**，这是运维日常最高频的工作，也是面试必考。生产环境里，当网站变慢、被刷、报错时，第一件事就是去 `access.log` 里找答案。

这道题的核心是让你**把 `awk / sort / uniq / head` 组合起来做统计**——也就是常说的"文本三剑客"实战。相比备份脚本，它几乎不涉及文件系统操作，纯粹考验你**对文本流的管道化处理能力**。

### 日志格式（Nginx combined 格式）

以空格分隔，字段位置固定：

```
192.168.1.10 - - [20/Sep/2026:08:00:01 +0800] "GET /index.html HTTP/1.1" 200 612 "-" "Mozilla/5.0"
```

| 字段 | 位置 | 含义 |
|------|------|------|
| `$1` | 第 1 列 | 客户端 IP |
| `$4` | 第 4 列 | 访问时间 `[20/Sep/2026:08:00:01` |
| `$6` | 第 6 列 | 请求方法（带前引号，如 `"GET`） |
| `$7` | 第 7 列 | 请求的 URL 路径（如 `/index.html`） |
| `$9` | 第 9 列 | HTTP 状态码（200/404/500…） |
| `$10` | 第 10 列 | 响应体大小（字节） |

## 脚本编写要求

编写 `log_analyzer.sh`，接收一个日志文件路径，输出以下统计：

1. **总请求数**（日志总行数）
2. **独立 IP 数（UV）**：去重后的 IP 数量
3. **状态码分布**：每种状态码（200/404/500…）各出现多少次，按次数从高到低排序
4. **Top N 访问 IP**：访问次数最多的 N 个 IP，格式 `次数 IP`（N 默认 10）
5. **Top N 访问 URL**：被请求次数最多的 N 个 URL
6. **（进阶）Top N 404 URL**：只统计状态码为 404 的请求里，哪些 URL 被访问最多（排查死链/扫描很有用）

参数要求：

- 用法：`./log_analyzer.sh [-n TOP_N] <日志文件>`
- `-n` 指定 Top N 的数量，正整数，默认 `10`；用 `getopts` 解析（延续昨天的写法）
- 日志文件不存在或不可读时报错退出；参数错误退出码 `2`

## 考察知识点

- `awk '{print $N}'` 提取列、`awk '$9 == 404'` 条件过滤、`awk 'END{print NR}'` 汇总
- `sort` / `sort -u` / `sort -rn` 排序与去重
- `uniq -c` 相邻行计数（**必须先 sort 再 uniq**，这是易错点）
- `head -n N` 取 Top N
- `wc -l` 行数统计
- `getopts` 复用昨天的选项解析

## 验收标准

1. 日志文件不存在时，报错退出（退出码 `1`）。
2. 不传参数时打印用法，退出码 `2`。
3. 对上面 15 行测试数据，各项统计数字正确（对照输出示例）。
4. `-n 3` 时 Top 输出只显示 3 行；不传 `-n` 时默认显示 10 行。
5. 状态码分布和 Top IP 都按次数**从高到低**排序。

## 参考答案（写完后对照）

```bash
#!/bin/bash
set -euo pipefail

log_error() { echo -e "\033[31m[ERROR] $(date '+%F %T') $*\033[0m" >&2; }
log_info()  { echo -e "\033[32m[INFO]  $(date '+%F %T') $*\033[0m"; }

usage() {
    log_error "用法: $0 [-n TOP_N] <日志文件>"
    log_error "示例: $0 -n 10 /var/log/nginx/access.log"
}

TOP_N=10

while getopts "n:h" opt; do
    case "$opt" in
        n)
            if [[ "$OPTARG" =~ ^[0-9]+$ ]] && [ "$OPTARG" -ge 1 ]; then
                TOP_N="$OPTARG"
            else
                log_error "-n 需要正整数"
                exit 2
            fi
            ;;
        h) usage; exit 0 ;;
        ?) usage; exit 2 ;;
    esac
done
shift $((OPTIND - 1))

if [ $# -ne 1 ]; then
    usage
    exit 2
fi

LOG_FILE="$1"

if [ ! -f "$LOG_FILE" ]; then
    log_error "日志文件不存在: $LOG_FILE"
    exit 1
fi
if [ ! -r "$LOG_FILE" ]; then
    log_error "日志文件不可读: $LOG_FILE"
    exit 1
fi

echo "===== 总请求数 ====="
awk 'END { print NR }' "$LOG_FILE"

echo "===== 独立 IP 数（UV） ====="
awk '{ print $1 }' "$LOG_FILE" | sort -u | wc -l

echo "===== 状态码分布 ====="
awk '{ print $9 }' "$LOG_FILE" | sort | uniq -c | sort -rn

echo "===== Top ${TOP_N} 访问 IP ====="
awk '{ print $1 }' "$LOG_FILE" | sort | uniq -c | sort -rn | head -n "$TOP_N"

echo "===== Top ${TOP_N} 访问 URL ====="
awk '{ print $7 }' "$LOG_FILE" | sort | uniq -c | sort -rn | head -n "$TOP_N"

echo "===== Top ${TOP_N} 404 URL ====="
awk '$9 == 404 { print $7 }' "$LOG_FILE" | sort | uniq -c | sort -rn | head -n "$TOP_N"
```

## 关键点讲解与运维最佳实践

1. **"先 `sort` 再 `uniq -c`"是铁律。**
   `uniq` 只会合并**相邻**的重复行。如果直接 `awk ... | uniq -c`，同一 IP 分散在不同位置时会被重复计数。所以统计套路永远是：`提取列 → sort（让相同值相邻）→ uniq -c（计数）→ sort -rn（按次数倒序）→ head -n N（取前 N）`。

2. **`awk 'END { print NR }'` 与 `wc -l` 的区别。**
   两者都能数行数，但 `awk END` 是在 awk 内部完成，适合需要同时做其它统计时复用；`wc -l` 更直观。本题用 `wc -l` 即可。

3. **`awk '$9 == 404 { print $7 }'` 是"条件过滤 + 投影"的经典写法。**
   前面的 `$9 == 404` 是条件（只处理状态码为 404 的行），大括号里是动作（打印第 7 列）。这种"条件 + 动作"的结构是 awk 的灵魂。

4. **`sort -u` 与 `sort | uniq` 的区别。**
   `sort -u` 直接输出去重后的行，适合"数 UV"；`sort | uniq -c` 会额外给出每行出现次数，适合"统计频率"。本题"独立 IP 数"用 `sort -u | wc -l`，"Top IP"用 `sort | uniq -c`。

5. **日志分析脚本永远只读、不写。**
   和备份脚本不同，分析类脚本对日志文件**绝不追加、绝不修改**（生产日志一旦被改，审计就失效了）。所以这类脚本没有"破坏性操作"，但要注意大文件性能——`awk` 是流式处理，能扛住几个 GB 的日志；而 `sort` 需要把中间结果读进内存/临时盘，超大文件排序时要留意磁盘空间。

### 进阶提示（下一阶段再扩展）

- 加 `--minute` / `--hour` 参数，按 `$4` 时间字段统计每分钟/每小时的请求量（配合 `cut -d: -f` 截取时间）。
- 加"响应时间"统计：如果日志格式带 `$request_time`（在日志末尾），可用 awk 求平均、P99 响应时间，这是性能排查的利器。
- 分析"慢请求"：找出响应体最大或响应时间最长的 Top N 请求。
