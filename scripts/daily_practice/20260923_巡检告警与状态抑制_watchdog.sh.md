# 每日 Shell 运维实战练习 · 2026-09-23

## 题目：巡检告警与状态抑制脚本（watchdog.sh）

### 题目背景

你上一题已经写出了 `healthcheck.sh`，能对 HTTP / TCP / 进程做健康探测，并返回 `0/1/2` 退出码。

但真实生产里，**“能探测”不等于“能值班”**。如果一个服务连续 10 分钟故障，你的巡检每分钟跑一次、每次都发一条告警，那就不是监控，而是**告警风暴**。SRE 更看重的是：

1. **首次故障要及时告警**
2. **持续故障不要重复刷屏**
3. **恢复时要补一条恢复通知**
4. **状态要可落盘，脚本重跑后还能记得上次结果**

今天这题就是把你的 `healthcheck.sh` 往“可值班”的方向推进一步：写一个 `watchdog.sh`，调用 `healthcheck.sh`，把结果保存到状态文件中，并实现**状态变化才告警**。

---

## 脚本编写要求

编写 `watchdog.sh`，实现：

1. **命令行**
   - `./watchdog.sh -c <巡检配置> -s <状态文件> [-l <日志文件>]`
   - `-c`：传给 `healthcheck.sh` 的巡检配置文件
   - `-s`：状态文件路径（必须持久化保存）
   - `-l`：告警日志文件，可选；若不传则默认 `/tmp/watchdog_alert.log`

2. **调用已有脚本**
   - 调用你上一题的 `healthcheck.sh`
   - 保留其 stdout/stderr 到临时文件，供后续判断和落盘
   - 根据 `healthcheck.sh` 的退出码判断本次巡检总体状态：
     - `0`：全部健康，记为 `UP`
     - `1`：存在异常，记为 `DOWN`
     - `2`：配置或用法错误，记为 `ERROR`

3. **状态文件设计**
   - 状态文件至少保存以下字段：
     - 上一次状态（`UP` / `DOWN` / `ERROR`）
     - 上一次检查时间
   - 如果状态文件不存在，脚本应自动初始化
   - 推荐格式：`KEY=VALUE`，例如：

```bash
LAST_STATUS=UP
LAST_CHECK_TIME=2026-09-23 08:00:00
```

4. **状态变化才告警**
   - 规则如下：
     - 上次 `UP`，本次 `DOWN`：写入一条**故障告警**
     - 上次 `DOWN`，本次 `DOWN`：**不重复告警**
     - 上次 `DOWN`，本次 `UP`：写入一条**恢复通知**
     - 上次 `UP`，本次 `UP`：不写告警
     - 本次 `ERROR`：写一条**脚本错误/配置错误告警**
   - 告警先写到日志文件，不要求发钉钉/邮件

5. **日志内容**
   - 告警日志每条至少包含：
     - 时间戳
     - 状态变化（例如 `UP -> DOWN`）
     - 配置文件名
     - `healthcheck.sh` 的关键输出摘要

6. **退出码**
   - `watchdog.sh` 自身也要返回明确退出码：
     - 当前状态 `UP` → `exit 0`
     - 当前状态 `DOWN` → `exit 1`
     - 当前状态 `ERROR` → `exit 2`

## 测试步骤

```bash
# 1. 准备巡检配置（沿用上一题）
cat > /tmp/healthcheck.conf <<'EOF'
http web   http://127.0.0.1:8080/health
tcp  ssh   127.0.0.1:22
EOF

# 2. 第一次执行：若服务正常，应初始化状态为 UP，不写故障告警
./watchdog.sh -c /tmp/healthcheck.conf -s /tmp/watchdog.state
echo $?
cat /tmp/watchdog.state

# 3. 故意加一个坏目标，让 healthcheck 变成 DOWN
echo "tcp dead 127.0.0.1:9999" >> /tmp/healthcheck.conf
./watchdog.sh -c /tmp/healthcheck.conf -s /tmp/watchdog.state -l /tmp/watchdog.log
echo $?
cat /tmp/watchdog.log

# 4. 再执行一次（仍然 DOWN），应不重复写新的故障告警
./watchdog.sh -c /tmp/healthcheck.conf -s /tmp/watchdog.state -l /tmp/watchdog.log

# 5. 删除坏目标，恢复为 UP，应写恢复通知
sed -i '/tcp dead/d' /tmp/healthcheck.conf
./watchdog.sh -c /tmp/healthcheck.conf -s /tmp/watchdog.state -l /tmp/watchdog.log
cat /tmp/watchdog.log
```

## 考察知识点

- 调用已有脚本并接收退出码：`if ./healthcheck.sh ...; then ... fi`
- 捕获命令输出到临时文件：`mktemp`、重定向 `>file 2>&1`
- 读取/写入状态文件：`source` / `grep '^KEY='` / 重写文件
- 状态机思想：`UP -> DOWN -> UP`
- 告警抑制（Alert Suppression）与恢复通知（Recovery Notice）
- 日志追加：`tee -a` 或 `>>`

---

## 验收标准

1. 状态文件不存在时能自动初始化。
2. 第一次执行若为 `UP`，状态文件被正确写入，退出码为 `0`。
3. 从 `UP` 变为 `DOWN` 时，只写一条故障告警，退出码为 `1`。
4. 持续 `DOWN` 多次执行，不重复写故障告警。
5. 从 `DOWN` 恢复到 `UP` 时，写一条恢复通知，退出码为 `0`。
6. `healthcheck.sh` 返回 `2` 时，`watchdog.sh` 也返回 `2`，并写错误告警。
7. 告警日志中包含时间戳、状态变化、配置文件、摘要。

## 参考答案（写完后对照）

```bash
#!/bin/bash
set -euo pipefail

CONFIG=""
STATE_FILE=""
ALERT_LOG="/tmp/watchdog_alert.log"
HEALTHCHECK_SCRIPT="$(dirname "$0")/healthcheck.sh"

log_error() { echo -e "\033[31m[ERROR] $(date '+%F %T') $*\033[0m" >&2; }
log_info()  { echo -e "\033[32m[INFO]  $(date '+%F %T') $*\033[0m"; }
log_warn()  { echo -e "\033[33m[WARN]  $(date '+%F %T') $*\033[0m"; }

usage() {
    log_error "用法: $0 -c <巡检配置> -s <状态文件> [-l <日志文件>]"
}

while getopts ":c:s:l:h" opt; do
    case "$opt" in
        c) CONFIG="$OPTARG" ;;
        s) STATE_FILE="$OPTARG" ;;
        l) ALERT_LOG="$OPTARG" ;;
        h) usage; exit 0 ;;
        \?) usage; exit 2 ;;
    esac
done
shift $((OPTIND - 1))

if [ -z "$CONFIG" ] || [ -z "$STATE_FILE" ]; then
    usage
    exit 2
fi

if [ ! -x "$HEALTHCHECK_SCRIPT" ]; then
    log_error "healthcheck.sh 不存在或不可执行: $HEALTHCHECK_SCRIPT"
    exit 2
fi

LAST_STATUS="UNKNOWN"
LAST_CHECK_TIME=""
if [ -f "$STATE_FILE" ]; then
    # shellcheck disable=SC1090
    source "$STATE_FILE"
fi

TMP_OUT="$(mktemp)"
trap 'rm -f "$TMP_OUT"' EXIT

CURRENT_TIME="$(date '+%F %T')"
CURRENT_STATUS="ERROR"

if "$HEALTHCHECK_SCRIPT" -c "$CONFIG" >"$TMP_OUT" 2>&1; then
    CURRENT_STATUS="UP"
else
    rc=$?
    case "$rc" in
        1) CURRENT_STATUS="DOWN" ;;
        2) CURRENT_STATUS="ERROR" ;;
        *) CURRENT_STATUS="ERROR" ;;
    esac
fi

SUMMARY="$(grep '巡检结束:' "$TMP_OUT" | tail -n 1 || true)"
[ -z "$SUMMARY" ] && SUMMARY="$(tail -n 1 "$TMP_OUT" || true)"

log_info "上次状态: $LAST_STATUS"
log_info "本次状态: $CURRENT_STATUS"

append_alert() {
    local tag="$1"
    echo "[$CURRENT_TIME] $tag $LAST_STATUS -> $CURRENT_STATUS config=$CONFIG summary=\"$SUMMARY\"" >> "$ALERT_LOG"
}

case "$LAST_STATUS:$CURRENT_STATUS" in
    UNKNOWN:UP)
        ;;
    UNKNOWN:DOWN|UP:DOWN)
        append_alert "ALERT"
        log_warn "检测到状态变化: $LAST_STATUS -> $CURRENT_STATUS，已写入告警日志"
        ;;
    DOWN:DOWN)
        log_info "服务仍处于 DOWN，已抑制重复告警"
        ;;
    DOWN:UP)
        append_alert "RECOVERY"
        log_info "服务已恢复，已写入恢复通知"
        ;;
    *:ERROR)
        append_alert "ERROR"
        log_error "巡检脚本执行异常，已写入错误告警"
        ;;
esac

cat > "$STATE_FILE" <<EOF
LAST_STATUS=$CURRENT_STATUS
LAST_CHECK_TIME=$CURRENT_TIME
EOF

case "$CURRENT_STATUS" in
    UP) exit 0 ;;
    DOWN) exit 1 ;;
    ERROR) exit 2 ;;
esac
exit 2
```

## 关键点讲解与运维最佳实践

1. **监控最怕的不是没告警，而是乱告警。**  
   连续 DOWN 每分钟发一次，不会让人更快处理，只会把人吵麻。真实值班系统一定有“状态变化才通知”的机制。

2. **状态文件本质上就是最小版状态机存储。**  
   你现在只是保存 `LAST_STATUS`，后面完全可以扩展出：
   - 连续失败次数
   - 首次故障时间
   - 最近一次恢复时间

3. **`healthcheck.sh` 和 `watchdog.sh` 的职责边界要清楚。**  
   - `healthcheck.sh`：只负责“检查”
   - `watchdog.sh`：负责“记忆、抑制、告警”

4. **这已经接近生产监控链路了。**  
   下一阶段只要把 `append_alert` 从“写文件”换成“发 webhook/邮件”，你就已经做出了一个最小可用的监控告警器。
