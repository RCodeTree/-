# 每日 Shell 运维实战练习 · 2026-09-24

## 题目：日志轮转与清理脚本（log_clean.sh）

### 题目背景
前两题你把「巡检 → 告警抑制」这条监控链路打通了（`healthcheck.sh` + `watchdog.sh`）。但 SRE 日常还有一类更"脏"却更必须的活：**磁盘治理**——生产服务器磁盘写满，90% 的元凶是日志。

日志治理的关键不是"删文件"，而是**有策略、可审计、可回滚**地控制日志生命周期。今天把"删除"这个高危动作，包装成一次**先演练、后执行**的受控操作。这是运维安全设计的核心：**任何破坏性动作，都要能先看清楚，再决定做不做。**

> ⚠️ 生产高危操作警示：本题涉及删除/压缩文件。脚本设计上**默认 dry-run**，必须显式加 `-e` 才真正改动文件。请务必先在 `/tmp` 的测试目录里跑通，**绝不要**第一版就对着 `/var/log` 真跑。执行前先确认：① 确认目标目录；② 确认无正在写入的关键日志；③ 确认有回滚/快照预案。

## 脚本编写要求

编写 `log_clean.sh`，实现：

1. **命令行**：`./log_clean.sh -d <日志目录> [-p <保留天数>] [-z] [-e] [-l <审计日志>] [-h]`
   - `-d`：要治理的日志目录（**必填**）
   - `-p`：保留最近 N 天（默认 `7`），**正整数**
   - `-z`：压缩模式——把超期 `*.log` 用 `gzip` 归档为 `*.gz`（**压缩成功后再删原文件**）
   - `-e`：执行模式——真正删除/压缩；**不加 `-e` 时默认 dry-run，只打印将处理哪些文件**
   - `-l`：审计日志文件（默认 `/tmp/log_clean.log`）
   - `-h`：打印用法

2. **目录与参数校验（安全底线）**
   - `-d` 目录不存在 → 报错 `exit 1`
   - `-p` 非正整数 → 用法错误 `exit 2`
   - **危险目录防护**：拒绝操作 `/`、`/etc`、`/bin`、`/sbin`、`/usr`、`/lib`、`/boot`、`/root`、`/dev`、`/proc`、`/sys`（直接拒绝并 `exit 1`）。这是防"手滑 `-d /` 删库跑路"的最后一道防线。

3. **匹配与统计**
   - 用 `find <目录> -type f -name '*.log' -mtime +N` 找出「超过 N 天未修改」的日志
   - 打印命中文件数 + 合计大小
   - dry-run 时**逐行列出**文件路径

4. **执行（仅 `-e` 时）**
   - 普通模式：删除命中的 `*.log`
   - `-z` 模式：对每个文件 `gzip`；**压缩成功后**才删原 `.log`；压缩失败保留原文件
   - 结束后打印「共命中 N 个，成功处理 M 个」

5. **审计日志**：每次运行（含 dry-run）把「时间、模式、目录、保留天数、命中数、处理结果」追加到 `-l` 文件

6. **退出码**：`0` 成功；`1` 运行错误；`2` 用法错误

## 测试步骤

```bash
# 1. 造测试目录与"新老"日志（用 touch 伪造修改时间）
mkdir -p /tmp/logtest
echo old > /tmp/logtest/app-1.log
echo old > /tmp/logtest/app-2.log
echo new > /tmp/logtest/app-3.log
touch -d "10 days ago" /tmp/logtest/app-1.log
touch -d "8 days ago"  /tmp/logtest/app-2.log   # 超过默认 7 天，应命中
# app-3.log 保持"今天"，应被保留

# 2. dry-run（默认模式，不加 -e）：只列出，不删除
./log_clean.sh -d /tmp/logtest -p 7
ls /tmp/logtest          # 文件应全部还在

# 3. 真删（加 -e）
./log_clean.sh -d /tmp/logtest -p 7 -e
ls /tmp/logtest          # app-1/app-2 消失，app-3 保留

# 4. 压缩模式（-z）
echo old > /tmp/logtest/app-4.log
touch -d "9 days ago" /tmp/logtest/app-4.log
./log_clean.sh -d /tmp/logtest -p 7 -z -e
ls /tmp/logtest          # 出现 app-4.log.gz，原 app-4.log 消失

# 5. 危险目录防护
./log_clean.sh -d / -p 7 -e
echo $?                  # 应被拒绝，退出码 1
```

## 考察知识点

- `find -type f -name '*.log' -mtime +N` 的**时间过滤**（`+N` = 早于 N 天前）
- `getopts` 布尔开关（`-z`/`-e` 不带值）+ `:` 与 `\?` 的错误处理
- **安全默认设计**：破坏性脚本默认 dry-run，显式开关才执行
- **危险目录黑名单** + `readlink -f` 解析真实路径
- `mapfile` 把 `find` 结果读进数组（**安全处理带空格的文件名**）
- `gzip -f` 的**成功后才删源文件**（防数据丢失）
- 审计日志追加与 `exit 0/1/2` 退出码语义

---

## 验收标准

1. 不传 `-d` 或 `-p` 非正整数时，打印用法并 `exit 2`。
2. `-d` 目录不存在时，报错并 `exit 1`。
3. **不加 `-e` 时，目录内文件零改动**（dry-run 生效）。
4. 加 `-e` 后，只有 `mtime > N 天`的 `*.log` 被删除，新日志保留。
5. `-z -e` 模式下，命中文件变成 `.gz`，原 `.log` 不存在；若某文件压缩失败，其原文件必须保留。
6. `-d /`（或 `/etc` 等）被拒绝且 `exit 1`。
7. 审计日志文件里能看到每次运行的记录（含 dry-run）。

## 参考答案（写完后对照）

```bash
#!/bin/bash
set -euo pipefail

LOG_DIR=""
KEEP_DAYS=7
MODE="delete"                 # delete | compress
EXECUTE=false
AUDIT_LOG="/tmp/log_clean.log"

log_info()  { echo -e "\033[32m[INFO]  $(date '+%F %T') $*\033[0m"; }
log_warn()  { echo -e "\033[33m[WARN]  $(date '+%F %T') $*\033[0m"; }
log_error() { echo -e "\033[31m[ERROR] $(date '+%F %T') $*\033[0m" >&2; }
audit()     { echo "[$(date '+%F %T')] $*" >> "$AUDIT_LOG"; }

usage() {
    log_error "用法: $0 -d <日志目录> [-p <保留天数>] [-z] [-e] [-l <审计日志>]"
    log_error "  -d 要治理的日志目录(必填) | -p 保留天数(默认7) | -z 压缩模式"
    log_error "  -e 执行(默认dry-run)      | -l 审计日志 | -h 帮助"
    log_error "示例: $0 -d /var/log/app -p 7 -z -e"
}

# 危险目录黑名单
is_dangerous_dir() {
    case "$1" in
        /|/etc|/bin|/sbin|/usr|/lib|/lib64|/boot|/root|/dev|/proc|/sys) return 0 ;;
        *) return 1 ;;
    esac
}

while getopts ":d:p:zel:h" opt; do
    case "$opt" in
        d) LOG_DIR="$OPTARG" ;;
        p) KEEP_DAYS="$OPTARG" ;;
        z) MODE="compress" ;;
        e) EXECUTE=true ;;
        l) AUDIT_LOG="$OPTARG" ;;
        h) usage; exit 0 ;;
        \?) usage; exit 2 ;;
        :)  log_error "选项 -$OPTARG 需要参数值"; usage; exit 2 ;;
    esac
done
shift $((OPTIND - 1))

# 参数校验
if [ -z "$LOG_DIR" ]; then usage; exit 2; fi
if ! [[ "$KEEP_DAYS" =~ ^[0-9]+$ ]] || [ "$KEEP_DAYS" -lt 1 ]; then
    log_error "-p 需要正整数"; exit 2
fi
if [ ! -d "$LOG_DIR" ]; then
    log_error "日志目录不存在: $LOG_DIR"; exit 1
fi

# 危险目录防护（解析软链接后的真实路径再判断）
REAL_DIR="$(readlink -f "$LOG_DIR")"
if is_dangerous_dir "$REAL_DIR"; then
    log_error "拒绝操作危险目录: $REAL_DIR（防止误删系统文件）"
    exit 1
fi

# 匹配目标文件（数组方式，兼容文件名含空格）
mapfile -t TARGETS < <(find "$REAL_DIR" -type f -name '*.log' -mtime +"$KEEP_DAYS" 2>/dev/null)

if [ "${#TARGETS[@]}" -eq 0 ]; then
    log_info "没有超过 ${KEEP_DAYS} 天的 .log 文件，无需处理"
    audit "mode=$MODE dir=$REAL_DIR keep=${KEEP_DAYS}d execute=$EXECUTE hit=0"
    exit 0
fi

TOTAL_SIZE="$(du -ch "${TARGETS[@]}" 2>/dev/null | tail -1 | cut -f1)"

# dry-run：只看不动
if [ "$EXECUTE" = false ]; then
    log_warn "[dry-run] 以下 ${#TARGETS[@]} 个文件将被处理（模式: $MODE，合计约 $TOTAL_SIZE）:"
    printf '  %s\n' "${TARGETS[@]}"
    log_info "本次为演练，未做任何改动。确认无误后加 -e 执行。"
    audit "mode=$MODE dir=$REAL_DIR keep=${KEEP_DAYS}d execute=false hit=${#TARGETS[@]}"
    exit 0
fi

# 真正执行
done_count=0
for f in "${TARGETS[@]}"; do
    if [ "$MODE" = "compress" ]; then
        if gzip -f "$f"; then            # gzip -f 成功后才删原文件
            log_info "已压缩: $f -> $f.gz"
            done_count=$((done_count + 1))
        else
            log_error "压缩失败，保留原文件: $f"
        fi
    else
        if rm -f "$f"; then
            log_info "已删除: $f"
            done_count=$((done_count + 1))
        else
            log_error "删除失败: $f"
        fi
    fi
done

log_info "处理完成: 共命中 ${#TARGETS[@]} 个，成功处理 $done_count 个（模式: $MODE，约 $TOTAL_SIZE）"
audit "mode=$MODE dir=$REAL_DIR keep=${KEEP_DAYS}d execute=true hit=${#TARGETS[@]} done=$done_count"
exit 0
```

## 关键点讲解与运维最佳实践

1. **破坏性脚本的第一设计原则：默认不破坏。** 把它做成"默认 dry-run、显式 `-e` 才动手"，等价于给你自己加了个人工确认环节。真实运维平台里的"发布预览""变更单""二次确认"都是这个思想的延伸。

2. **危险目录黑名单 = 最后一道防线。** 人一定会手滑。`readlink -f` 先把软链接还原成真实路径，再和黑名单比对，能挡住 `-d /` 这类灾难。这不是过度设计，而是所有 `rm` 类脚本的标配。

3. **`find -mtime +N` 记牢含义。** `+7` 表示"修改时间在 **7×24 小时之前**"，即早于 7 天；`-7` 是"最近 7 天内"；`7` 是"正好第 7 天那一天"。用错符号方向，排除结果会完全相反。

4. **`gzip` 的顺序决定数据安全。** `gzip -f file` 会生成 `file.gz` 并删除原 `file`；只有它**返回 0** 才说明压缩成功。若压缩失败却先删原文件，就是**数据丢失**。所以"成功才删源"是铁律。

5. **`mapfile -t` 代替 `for f in $(find ...)`。** 后者在文件名含空格/换行时会被拆错。`mapfile` 按行读入数组，`"${TARGETS[@]}"` 加引号展开，才能安全处理任意文件名。这是处理文件列表的标准姿势。

6. **审计日志让"谁在什么时候删了什么"可追溯。** dry-run 也记一笔，这样你能从日志看出"某次演练命中了多少、真正执行了几次"，出问题时能复盘。

### 进阶提示（下一阶段再扩展）

- **按文件名日期而非 mtime** 治理（如 `app-2026-09-01.log`）：用 `grep -oE '[0-9]{4}-[0-9]{2}-[0-9]{2}'` 提取日期再比较。
- 加**保护白名单**：永不处理 `current.log` / `error.log` 等"正在写"的日志。
- 加**磁盘水位触发**：只有使用率 ≥ 阈值时才清理（复用 `backup.sh` 的 `df` 逻辑）。
- 归档到**冷存储**（先 `tar` 再删），而非直接删。
- 最终形态是 **logrotate**：本题理解原理后，生产上应优先用系统的 `logrotate`。
