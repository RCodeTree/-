## 题目：备份恢复与演练脚本（restore.sh）

### 题目背景

前面两题你完成了"备份"的完整链路：`backup.sh` 能把目录打成 `.tar.gz`、校验完整性、清理旧备份。但运维圈有句铁律——**备份的意义不在于"备份"，而在于"能恢复"**。

很多团队备份做得勤，却从没演练过恢复，真到数据丢失那天才发现：备份文件早损坏了、恢复流程没人会跑、或者恢复时把现有数据覆盖了。今天写 `restore.sh`，把 `backup.sh` 生成的备份**安全地恢复出来**，并支持"演练模式"。

这道题会引入几个**新的安全概念**：路径穿越防护、防覆盖、dry-run 演练，这也是从"会写脚本"走向"懂安全"的关键一步。

---

## 脚本编写要求

编写 `restore.sh`，接收一个备份文件和目标目录，实现：

1. **参数**：`./restore.sh [-d] [-f] <备份文件> <目标目录>`
   - `-d`（dry-run，演练模式）：只列出将恢复的文件，**不实际解压**
   - `-f`（force，强制）：目标目录非空时也允许恢复（覆盖）
   - 用 `getopts` 解析（延续前两题写法）
2. **校验备份文件**：不存在、不可读、或不是有效的 `.tar.gz`（`tar -tzf` 无法列出）都要报错退出。
3. **路径穿越防护（安全核心）**：用 `tar -tzf` 列出备份内容，检查是否存在 `..` 路径组件；若存在则拒绝恢复，防止恶意压缩包把文件写到目标目录之外。
4. **防覆盖**：目标目录已非空、且未传 `-f` 时，拒绝恢复（报错退出），提示用户"加 `-f` 或先备份现有数据"。
5. **演练模式**：传 `-d` 时，只打印"将要恢复哪些文件"，不真正解压。
6. **实际恢复 + 后置校验**：`tar -xzf 备份 -C 目标目录` 解压，结束后打印恢复了多少个文件，并列出恢复内容。

## 考察知识点

- `tar -tzf`（列出内容）与 `tar -xzf`（解压）、`-C` 指定解压目录
- **路径穿越**的原理与防护（`grep -E '(^|/)\.\.(/|$)'`）
- 防覆盖 + `--force` 的安全设计
- `--dry-run` 演练模式（可观测性 / "先看后做"）
- `getopts` 布尔开关（`-d`/`-f` 不带参数值）
- `ls -A` 判断目录是否非空

---

## 验收标准

1. 备份文件不存在或不是有效 tar.gz 时，报错退出（退出码 `1`）。
2. 不传参数时打印用法，退出码 `2`。
3. `-d` 演练模式只打印文件列表，目标目录里**不产生任何文件**。
4. 目标目录非空且未加 `-f` 时，恢复被拒绝。
5. 加 `-f` 后能覆盖恢复成功，且恢复出的文件内容正确（`cat /tmp/restore/mysite/www/index.html` 输出 `hello`）。
6. 对一个包含 `../` 条目的恶意压缩包，脚本能识别并拒绝恢复。

## 参考答案（写完后对照）

```bash
#!/bin/bash
set -euo pipefail

log_error() { echo -e "\033[31m[ERROR] $(date '+%F %T') $*\033[0m" >&2; }
log_info()  { echo -e "\033[32m[INFO]  $(date '+%F %T') $*\033[0m"; }
log_warn()  { echo -e "\033[33m[WARN]  $(date '+%F %T') $*\033[0m"; }

usage() {
    log_error "用法: $0 [-d] [-f] <备份文件> <目标目录>"
    log_error "  -d  演练模式（dry-run），只列出将恢复的文件，不实际解压"
    log_error "  -f  强制恢复（force），目标目录非空时允许覆盖"
    log_error "示例: $0 -d /backup/html_20260920.tar.gz /tmp/restore"
}

DRY_RUN=false
FORCE=false

while getopts "dfh" opt; do
    case "$opt" in
        d) DRY_RUN=true ;;
        f) FORCE=true ;;
        h) usage; exit 0 ;;
        ?) usage; exit 2 ;;
    esac
done
shift $((OPTIND - 1))

if [ $# -ne 2 ]; then
    usage
    exit 2
fi

BACKUP_FILE="$1"
RESTORE_DIR="$2"

# ==================== 校验备份文件 ====================
if [ ! -f "$BACKUP_FILE" ]; then
    log_error "备份文件不存在: $BACKUP_FILE"
    exit 1
fi
if [ ! -r "$BACKUP_FILE" ]; then
    log_error "备份文件不可读: $BACKUP_FILE"
    exit 1
fi

# 是否是有效的 tar.gz（能正常列出内容）
if ! tar -tzf "$BACKUP_FILE" >/dev/null 2>&1; then
    log_error "备份文件校验失败（不是有效的 tar.gz）: $BACKUP_FILE"
    exit 1
fi

# ==================== 路径穿越防护 ====================
# 检查备份里是否含有 ".." 路径组件（可能逃逸到目标目录之外）
if tar -tzf "$BACKUP_FILE" | grep -qE '(^|/)\.\.(/|$)'; then
    log_error "备份文件存在路径穿越风险（含 .. 条目），拒绝恢复"
    exit 1
fi

# ==================== 准备目标目录 ====================
if ! mkdir -p "$RESTORE_DIR"; then
    log_error "无法创建目标目录: $RESTORE_DIR"
    exit 1
fi

# ==================== 防覆盖 ====================
if [ -n "$(ls -A "$RESTORE_DIR")" ] && [ "$FORCE" = false ]; then
    log_error "目标目录非空，如需覆盖请加 -f 或先备份现有数据"
    log_error "目标目录: $RESTORE_DIR"
    exit 1
fi

# ==================== 演练模式 ====================
if [ "$DRY_RUN" = true ]; then
    log_info "演练模式：以下文件将被恢复到 $RESTORE_DIR（未实际执行）"
    tar -tzf "$BACKUP_FILE"
    exit 0
fi

# ==================== 实际恢复 ====================
log_info "开始恢复: $BACKUP_FILE -> $RESTORE_DIR"
tar -xzf "$BACKUP_FILE" -C "$RESTORE_DIR"

COUNT=$(tar -tzf "$BACKUP_FILE" | wc -l)
log_info "恢复完成，共恢复 ${COUNT} 个文件/目录"
```

## 关键点讲解与运维最佳实践

1. **"能恢复"才是备份的价值。**
   建议把 `restore.sh` 的演练纳入例行巡检（cron 定期跑一次 `-d` 或恢复到临时目录再删），确保备份文件一直处于"可恢复"状态，而不是等出事了才发现备份是坏的。

2. **路径穿越（Path Traversal）是什么？**
   一个恶意或异常的 tar 包可能包含 `../../etc/cron.d/evil` 这样的条目。恢复时如果盲目 `tar -xzf`，`../` 会把文件写到目标目录之外，甚至覆盖系统关键文件。`tar -tzf ... | grep -E '(^|/)\.\.(/|$)'` 就是检查"有没有 `..` 作为独立路径组件"。养成"恢复前先列内容检查"的习惯，不依赖 tar 的默认行为。

3. **防覆盖是数据安全底线。**
   恢复（尤其 `-f` 强制）本质是**覆盖写**，属于破坏性操作。所以默认拒绝"目标目录非空"，必须显式 `-f` 才放行——把"破坏"变成一次**有意识的决策**，而不是误操作。`ls -A`（含隐藏文件）比 `ls` 更严谨，能发现 `.git` 这类隐藏目录。

4. **`-d` dry-run 的"可观测性"思想。**
   演练模式遵循"先看后做"：把将要执行的动作完整打印出来，让操作者先确认、再决定是否真正执行。这个模式同样适用于 `rm`、`mv` 等危险操作——很多运维事故，都是因为"没看清楚就执行了"。

5. **`getopts` 的布尔开关。**
   `-d`、`-f` 是"不带参数值"的开关，`getopts "dfh"` 里 `d`/`f` 后面不加 `:`。用 `DRY_RUN=true` 这样的布尔变量记录状态，比用 `0/1` 更易读。

### 进阶提示（下一阶段再扩展）

- 支持**选择性恢复**：`restore.sh 备份 目标 --file 某个文件`，只从备份里抽出指定文件/目录（用 `tar -xzf ... -C ... 具体路径`）。
- 恢复前自动给"将被覆盖的现有数据"再做一次快照备份，形成"可回退"的恢复流程。
- 支持校验和：备份时记录文件的 `md5sum`/`sha256sum`，恢复后比对校验和，确保"恢复的 = 备份的"。
