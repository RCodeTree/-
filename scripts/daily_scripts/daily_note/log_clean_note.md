# log_clean.sh 日志轮转与清理脚本 · 复盘技术笔记

> 2026-09-24 每日练习复盘。记录「日志治理」这一题的设计思路、关键技术点，以及调试过程中真实踩过的坑，方便后续查阅与面试复盘。
> 核心一句话：**删文件谁都会删，难的是"有策略、可审计、可回滚"地删。**

---

## 一、脚本定位

| 维度 | 说明 |
|---|---|
| 解决的问题 | 生产磁盘被日志写满，需要**定期清理超期日志** |
| 安全设计 | **默认 dry-run**，必须显式 `-e` 才真正动文件；**危险目录黑名单**兜底 |
| 核心思想 | 把破坏性动作包装成「先演练 → 再确认 → 后执行」的受控流程 |

---

## 二、用法与参数

```bash
./log_clean.sh -d <日志目录> [-p <保留天数>] [-z] [-e] [-l <审计日志>] [-h]
```

| 选项 | 含义 | 默认值 |
|---|---|---|
| `-d` | 要治理的日志目录（**必填**） | 无 |
| `-p` | 保留最近 N 天（**正整数**） | `7` |
| `-z` | 压缩模式：超期 `*.log` → `gzip` 归档为 `*.gz` | 关闭（删除模式） |
| `-e` | 执行模式：真正删除/压缩；**不加 = dry-run** | 关闭 |
| `-l` | 审计日志文件 | `/tmp/log_clean.log` |
| `-h` | 打印用法 | — |

---

## 三、退出码语义

| 退出码 | 含义 |
|---|---|
| `0` | 成功（含 dry-run） |
| `1` | 运行错误：目录不存在 / 命中危险目录 / 权限不足 |
| `2` | 用法错误：缺 `-d` / `-p` 非正整数 / 非法参数 / 缺参数值 |

## 四、执行主干流程

```
解析参数(getopts)
      │
校验参数(顺序!): -z 空值 → -p 正整数 → 目录存在 → readlink 黑名单 → 权限
      │
find 收集超期文件 → mapfile 进数组 targets → 统计数量与体积
      │
  ┌───┴───────────────┐
  │ execute_mode=false │──► dry-run：只打印、写审计、exit 0
  └───┬───────────────┘
      │
  ┌───┴───────────────┐
  │ -e 且非 -z         │──► 删除模式：rm -f 逐文件 → 写审计 → exit 0
  └───┬───────────────┘
      │
  ┌───┴───────────────┐
  │ -e 且 -z           │──► 压缩模式：gzip -f 逐文件(失败保留原文件) → 写审计 → exit 0
  └───────────────────┘
```

## 五、关键技术点解析

### 1. `getopts` 的前导冒号与错误处理

```bash
while getopts ":d:p:zel:h" opt; do
  case "$opt" in
    ...
    \?) log_error "非法参数"; usage; exit 2 ;;   # 未知选项
    :)  log_error "缺参数值"; usage; exit 2 ;;   # 需要值却没给
  esac
done
```

* **前导 `:`**（`":d:p:..."`）：开启**静默错误模式**，`getopts` 不再自己打印报错，而是把错误塞进 `$opt`，交给我们的 `case` 处理。
* **`\?`**：命中非法选项（如 `-x`）。
* **`:`**：选项需要值但没给（如 `-d` 后面空着）。
* **`z e h`** 后不带 `:` → 是**布尔开关**，不带值。
* 两者错误都应归为**用法错误 → exit 2**。

### 2. 参数校验的**顺序**（安全底线里最容易被忽略的点）

正确顺序：**字符串校验在前，`readlink` 解析在最后**。

```bash
1) [ -z "$log_dir" ]           → usage; exit 2   # 先判断必填
2) [ -p 正整数 ]                → exit 2
3) [ -d "$log_dir" ] 不存在     → exit 1          # 此时只报 $log_dir，别引用 real_dir
4) real_dir=$(readlink -f ...)  → 再解析真实路径
5) 黑名单比对                   → exit 1
6) 权限检查                     → exit 1
```

**为什么顺序不能乱**：`real_dir` 要等第 4 步才赋值，前 3 步若引用它，在 `set -u` 下直接 `unbound variable` 崩掉。

### 3. `readlink -f` + 危险目录黑名单

```bash
real_dir=$(readlink -f "$log_dir")
for d in "${blacklist_dir[@]}"; do
  [ "$real_dir" = "$d" ] && { log_error "命中危险目录"; exit 1; }
done
```

* **必须 `readlink -f` 先解析真实路径**：`-d /etc/..`、`-d /tmp/../etc` 这类"绕过式"写法，软链接还原后才能和黑名单精确比对。
* 黑名单：`/ /etc /bin /sbin /usr /lib /boot /root /dev /proc /sys`。
* 这是防「手滑 `-d /` 删库跑路」的**最后一道防线**。

### 4. `mapfile -t` 收集文件列表（安全处理文件名）

```bash
mapfile -t targets < <(find "$log_dir" -type f -name '*.log' -mtime +$preserve_day 2>/dev/null)
```

* **不要**用 `for f in $(find ...)`：文件名含空格/换行会被拆成多个错误项。
* `mapfile -t` 按行读进数组（`-t` 去掉行尾换行符），配合 `"${targets[@]}"` 加引号展开，才能安全处理任意文件名。
* `2>/dev/null` 吞掉 find 的权限告警噪音。

### 5. `find -mtime +N` 的时间含义

| 写法 | 含义 |
|---|---|
| `+7` | 修改时间**早于** 7×24 小时（**超过 7 天**）← 本题用这个 |
| `-7` | 最近 7 天内修改 |
| `7` | 恰好第 7 天那一天 |

* 符号方向用错，命中的文件会**完全相反**（从"删老的"变成"删新的"）。

### 6. `du -ch` 汇总体积

```bash
clean_volume=$(du -ch "${targets[@]}" | tail -n 1 | awk '{print $1}')
```

* `-c` 输出**总计行**，`-h` 人类可读，`tail -n 1` 取总计，`awk '{print $1}'` 取值。
* 传**数组**而非命令替换结果，避免文件名空格问题。

### 7. 破坏性动作的"安全默认"

* 默认 `execute_mode=false` → 不加 `-e` 永远只演练，**等价于内置了一个人工确认环节**。
* 与真实运维平台的「发布预览 / 变更单 / 二次确认」是同一思想。

### 8. `gzip -f` 的顺序 = 数据安全

* `gzip -f file` 压缩成功后**自动删除原文件**并生成 `file.gz`。
* **只有它返回 0 才代表压缩成功**；失败必须 `continue` 保留原文件，否则就是**数据丢失**。
* 因此不需要再手动 `rm "$f"`——多余且危险。

### 9. 审计日志

* 三种模式（dry-run / delete / compress）**每次运行都追加一行**到 `-l` 文件。
* 作用：让「谁、何时、对哪个目录、按几天保留、命中多少、处理结果」**可追溯**，出问题能复盘。

## 六、踩坑复盘（本题调试中真实遇到的问题）

### 坑 1️⃣ 校验顺序反了 → 空值检查变"死代码" + `unbound variable`

```bash
# ✗ 错误：目录存在性检查跑在空值检查之前
if [ ! -d "$log_dir" ]; then
  log_error "日志目录不存在: $log_dir -> $real_dir!"   # real_dir 此时还未赋值
  exit 1
fi
if [ -z "$log_dir" ]; then ... fi                     # 永远到不了
```

* **后果 A**：不传 `-d` 时 `log_dir=""`，`[ ! -d "" ]` 为真 → 直接走"目录不存在"分支，`-z` 检查成**死代码**，退出码变成 1（应为 2）。
* **后果 B**：第 2 行引用了还没赋值的 `$real_dir`，在 `set -u` 下抛 `real_dir: unbound variable`，**友好报错打不出来**，脚本被 bash 报错终止。
* **修正**：把 `-z` 检查提到最前；报"目录不存在"时**只引 `$log_dir`**，`readlink` 放到目录确认存在之后。

### 坑 2️⃣ `((ok++))` 在 `set -e` 下的"自杀"退出码

```bash
ok=0
((ok++))        # ✗ ok 从 0 开始 → 表达式值=0 → 退出码=1 → set -e 立刻中断脚本
```

* **原理**：`((expr))` 的退出码取决于**表达式的值**；后置自增 `ok++` 的值是**自增前**的旧值。`ok` 初值 0 → `((0++))` 值为 0 → 返回码 1 → `set -e` 把脚本踢出。
* **症状**：压缩模式**压完第 1 个文件就中断**，连"已压缩"都不打印。
* **修正**（任选其一）：
  ```bash
  ok=$((ok + 1))          # ✅ 赋值语句，退出码稳定为 0（推荐）
  ((++ok))                # ✅ 前置自增，值为 1（真）→ 退出码 0
  ((ok++)) || true        # ✅ 显式兜底
  ```

### 坑 3️⃣ `-p` 校验正则过窄，误拒多位数

* 原写法把保留天数限制成单位数 → `-p 10`、`-p 30` 被误判为非法。
* **修正**：`[[ "$preserve_day" =~ ^[0-9]+$ ]] && [ "$preserve_day" -lt 1 ]` 才算「非正整数」。
* 记忆：**正则管"是不是数字"，数值比较管"是不是 ≥ 1"**，两者缺一不可。

### 坑 4️⃣ dry-run 的模式名写死为 `delete`

* 一开始 dry-run 输出恒显示「模式: delete」，即使带了 `-z`。
* **修正**：动态取当前模式 → `$([[ "$compress_mode" = true ]] && echo compress || echo delete)`。
* 教训：**预览信息必须和真实执行路径一致**，否则演练就失去意义。

### 坑 5️⃣ `getopts` 错误分支退出码是 1 不是 2

* 非法参数 / 缺参数值原本 `exit 1`，与「用法错误 = 2」的语义冲突。
* **修正**：统一 `exit 2`。

### 坑 6️⃣ 临时/审计写入与 `pipefail`

* `du -ch ... | tail | awk` 一旦 du 报错（个别文件无权限），`pipefail` 会让整条管道返回非 0 → `set -e` 中途中断。
* **建议**：`du -ch ... 2>/dev/null` 或给命令替换加 `|| echo 0` 兜底。

## 七、验收标准对照

| # | 验收标准 | 结果 | 实现位置 |
|---|---|---|---|
| 1 | 不传 `-d` 或 `-p` 非正整数 → 用法 + `exit 2` | ✅ | 空值检查在 `-p` 之前 |
| 2 | `-d` 目录不存在 → 报错 + `exit 1` | ✅ | 只引 `$log_dir`，无 unbound |
| 3 | 不加 `-e` 时目录内文件**零改动** | ✅ | dry-run 分支只 `find` 打印 |
| 4 | `-e` 后只有 `mtime > N 天` 的 `*.log` 被删 | ✅ | `find -mtime +N` |
| 5 | `-z -e` 命中文件变 `.gz`，原 `.log` 消失；失败保留原文件 | ✅ | `gzip -f` + `continue` |
| 6 | `-d /` 等被拒绝且 `exit 1` | ✅ | `readlink -f` + 黑名单 |
| 7 | 审计日志含每次运行记录（含 dry-run） | ✅ | 三分支均追加 |

## 八、测试步骤（务必只在 `/tmp` 里跑）

```bash
mkdir -p /tmp/logtest
for i in 1 2 3; do echo old > /tmp/logtest/app-$i.log; done
touch -d "10 days ago" /tmp/logtest/app-1.log
touch -d "8 days ago"  /tmp/logtest/app-2.log   # 超过 7 天，应命中
# app-3.log 保持今天，应保留

./log_clean.sh -d /tmp/logtest -p 7 ; echo $?      # 2) dry-run：只列不删，rc=0
ls /tmp/logtest
./log_clean.sh -d /tmp/logtest -p 7 -e ; echo $?   # 3) 真删：app-1/2 消失，rc=0
echo old > /tmp/logtest/app-4.log; touch -d "9 days ago" /tmp/logtest/app-4.log
./log_clean.sh -d /tmp/logtest -p 7 -z -e ; echo $? # 4) 压缩：出现 app-4.log.gz
./log_clean.sh -d / -p 7 ; echo $?                  # 5) 黑名单：拒绝，rc=1（切勿加 -e）
```

> ⚠️ 第 5 步**绝不能加 `-e`**，只验证它被拒绝。

## 九、可继续优化的点（进阶）

* **白名单保护**：永不处理 `current.log` / `error.log` 等"正在写"的日志。
* **按文件名日期治理**：`grep -oE '[0-9]{4}-[0-9]{2}-[0-9]{2}'` 提取日期再比较（适配 `app-2026-09-01.log`）。
* **磁盘水位触发**：仅当使用率 ≥ 阈值时才清理（复用 `df` 逻辑），避免无谓删除。
* **归档到冷存储**：先 `tar` 再删，而非直接删。
* **空命中早退**：0 个文件时打印提示 + 记审计后直接 `exit 0`，更干净。
* **最终形态**：生产上优先用系统自带的 **`logrotate`** —— 本题重在理解原理。
