# sort

`sort` 是 Linux 文本处理“三剑客”之一（另外两个是 `grep`、`awk`/`sed`），几乎在任何日志分析、数据统计场景中都会用到。它的核心作用是**对文本行进行排序**。

默认行为：`sort` 按**字符的 ASCII 编码顺序**（字典序）对整行进行升序排列。

***

### **1. 基础用法**

```bash
# 准备一份测试数据（建议在实验环境创建）
cat > /tmp/scores.txt <<'EOF'
tom 85 math
jerry 92 english
alice 78 math
bob 100 english
cindy 92 math
EOF

sort /tmp/scores.txt
```

***

### **2. 核心选项详解**

#### **a. 排序方式（决定"按什么规则排"）**

| 选项                      | 作用              | 说明                                                     |
| :---------------------- | :-------------- | :----------------------------------------------------- |
| **`-n`**                | **按数值排序**       | 不加 `-n` 时，`10` 会排在 `2` 前面（因为按字符 `1<2`）。**这是最常用的选项之一。** |
| **`-r`**                | **降序**（reverse） | 默认升序，加 `-r` 变降序                                        |
| **`-h`**                | **人类可读数值排序**    | 专门处理 `1K`、`2M`、`3G` 这类格式，`du -h` 的输出绝配                 |
| **`-V`**                | **版本号排序**       | 例如 `v1.2.10` 会正确排在 `v1.2.9` 之后                         |
| **`-M`**                | **月份排序**        | 识别 `JAN`\~`DEC` 三个字母的月份缩写（英文）                          |
| **`-g`** **/** **`-f`** | 浮点数 / 忽略大小写     | `-f` 让 A 和 a 视为相同                                      |

#### **b. 字段控制（决定"按哪一列排"）—— 重点**

这是 `sort` 最强大的部分，配合 **`-k`（key）** 和 **`-t`（separator）** 使用：

- **`-t`**：指定**列分隔符**（默认是空格/制表符）
- **`-k`**：指定**排序键**，格式 `-k 起始列[,结束列]`

```bash
# 以空格为分隔，按第 2 列（分数）数值降序排序
sort -t ' ' -k2 -nr /tmp/scores.txt
```

**输出逻辑**：先按第 2 列从大到小排，分数相同的再按字母排。

> **进阶语法**：`-k2,2n` 表示“只对第 2 列按数值排序”。注意 `n` 写在列号后面时，表示**该列**用数值规则，这比全局 `-n` 更精确。

#### **c. 去重（决定"要不要保留重复"）**

- **`-u`**：**去重**（unique）。排序后，相同行只保留一条。
  ```bash
  sort -u /tmp/scores.txt   # 完全相同的整行才会被去重
  ```

#### **d. 输出控制**

| 选项              | 作用                                                                             |
| :-------------- | :----------------------------------------------------------------------------- |
| **`-o <file>`** | **输出到文件**。关键：`-o` 支持**原地排序**（`sort file -o file`），而 `sort file > file` 会把文件清空！ |
| **`-c`**        | **检查是否已排序**，未排序则报错并指出问题行                                                       |
| **`-C`**        | 静默检查（不输出错误信息，只用退出码判断）                                                          |
| **`-s`**        | **稳定排序**（stable），保留值相等行的原始相对顺序                                                 |

### **3. SRE 实战场景**

#### **场景一：统计访问量最高的 IP（经典面试题）**

```bash
# 从 Nginx 日志中提取 IP -> 排序 -> 去重计数 -> 按次数降序取前 10
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -nr | head -10
```

**拆解这条命令的流水线（这是 SRE 必须掌握的思维）：**

1. `awk` 取出第 1 列 IP
2. **`sort`** 必须放在 `uniq` 前：因为 `uniq` 只能去除**相邻**的重复行
3. `uniq -c` 统计每个 IP 出现的次数
4. **`sort -nr`** 再按统计出的数字降序排（此时数字在第 1 列）
5. `head -10` 取 Top 10

#### **场景二：按磁盘占用排序**

```bash
du -sh /var/* | sort -rh
```

#### **场景三：按第 2 列数值排序，隔开的是冒号**

```bash
sort -t ':' -k3 -n /etc/passwd
```

***

### **4. 常见坑点（SRE 避坑）**

1. **`sort file > file`** **会清空文件**：Shell 会先创建空的 `file` 再执行 `sort`，导致读到空文件。**务必用** **`-o`**。
2. **数值列不加** **`-n`**：`9` 会排在 `80` 后面，这是新手最容易犯的错。
3. **`uniq`** **前必须先** **`sort`**：这是与 `sort` 组合时的铁律。
4. **大文件加** **`-S`**：处理超大日志（如几十 GB）时，可用 `-S 2G` 增大内存缓冲区，提升性能。
5. **默认排序受 Locale** 影响：某些环境下大小写排序结果不一致，可用 `LC_ALL=C sort` 强制按 ASCII 排序，保证结果稳定。
